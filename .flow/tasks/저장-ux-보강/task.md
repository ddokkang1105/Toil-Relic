# Task: 저장 UX 보강

## Goal

자동 저장과 불러오기 상태를 사용자가 이해하고 신뢰할 수 있도록, 저장 성공·실패·로드 가능 여부와 다음 행동을 콘솔 및 Unity에서 명확하게 전달한다.

## Scope

- 현재 자동 저장 시점과 사용자에게 노출되는 저장 피드백을 조사한다.
- Title의 Continue 상태, 저장 로드 결과, 플레이 중 저장 성공·실패 메시지의 우선순위와 수명을 정리한다.
- 저장 실패 또는 유효하지 않은 저장이 있을 때 사용자가 상황과 복구 행동을 이해할 수 있는 UX를 정의한다.
- 확정된 동작을 콘솔과 Unity에 적용하고 저장·상태 메시지 회귀 테스트로 검증한다.

## Non-goals

- 다중 저장 슬롯, 저장 이름 입력, 클라우드 동기화.
- 저장 데이터 형식의 전면 재설계 또는 버전 마이그레이션 프레임워크 도입.
- 저장 UX와 무관한 메인 메뉴·HUD 전체 리디자인.
- 수동 저장 기능 추가 여부는 discovery에서 필요성이 확인되기 전까지 범위에 포함하지 않는다.

## Acceptance criteria

- [ ] 사용자는 Title에서 Continue 가능 여부와 그 이유를 이해할 수 있다.
- [ ] 저장을 불러온 경우와 새 게임을 시작한 경우가 명확히 구분된다.
- [ ] 저장 실패는 성공 또는 일반 상태 메시지에 즉시 덮이지 않고, 문제와 다음 행동을 전달한다.
- [ ] 정상적인 자동 저장 피드백은 전투 결과나 핵심 행동 피드백을 방해하지 않는다.
- [ ] 저장 UX의 문구·표시 위치·표시 수명과 콘솔/Unity 적용 범위가 discovery에서 결정되고 테스트 가능한 계약으로 기록된다.
- [ ] 확정된 저장 시나리오에 대한 저장소 적합 검증이 통과한다.

## Constraints and risks

- 닫힌 선행 태스크 `main-menu-save-entry-flow`의 Title/Continue/New Game 계약을 보존한다.
- 기존 `BattleOutcome`, `LevelUp`, `SaveFailed`, `BattleLog` 표시 우선순위를 깨뜨리지 않는다.
- 테스트는 실제 사용자 저장 파일을 읽거나 삭제하지 않아야 한다.
- 저장 동작 또는 데이터 의미가 바뀌면 콘솔과 Unity 구현을 기능적으로 맞춘다.
- 저장 성공 피드백을 과도하게 노출하면 반복 행동마다 상태 영역이 시끄러워질 수 있으므로 빈도와 지속 시간을 discovery에서 결정한다.
