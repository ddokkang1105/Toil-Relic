# Task: 장비 시스템 도입

## Goal

플레이어가 장비를 보유·장착·저장할 수 있는 최소 장비 도메인을 콘솔과 Unity에 기능적으로 일치하게 도입한다.

## Scope

- 장비 타입, 장비 인스턴스 또는 식별 방식, 장착 슬롯 및 장비 능력치 모델을 정의한다.
- 플레이어 상태에 장비 보유 및 장착 상태를 추가하고 저장·불러오기를 지원한다.
- 첫 장비를 얻는 최소 경로와 콘솔·Unity에서 장착 상태를 확인할 수 있는 표현을 제공한다.
- 이후 장비 비교 태스크가 소비할 안정적인 조회 API를 제공한다.

### First-version decisions

- `Weapon` 슬롯 하나와 `AttackBonus` 하나만 지원한다.
- 장비는 정적 정의 ID로 보유·장착하며, 랜덤 옵션·인스턴스 ID는 지원하지 않는다.
- 기본 무기는 새·기존 플레이어 모두에게 보장하고, 첫 승리 보상으로 후보 무기 하나를 제공한다.

## Non-goals

- 장비 비교 UI와 능력치 차이 표시는 구현하지 않는다.
- 여러 장비 슬롯, 희귀도, 강화, 세트 효과, 랜덤 옵션은 첫 범위에서 제외한다.
- 기존 잡템·보물 재료·물약 시스템을 장비 시스템으로 재설계하지 않는다.

## Acceptance criteria

- [x] 콘솔과 Unity에 같은 최소 장비 타입·슬롯·능력치 규칙이 존재한다.
- [x] 플레이어는 장비를 보유하고 장착 상태를 변경할 수 있다. 후속 승인된 슬롯 규칙에 따라 주 무기는 항상 장착하고 선택 슬롯만 해제할 수 있다.
- [x] 장비 보유 및 장착 상태가 저장 후 불러오기에도 유지된다.
- [x] 기존 전투·인벤토리·제작·저장 흐름이 회귀 없이 동작한다.
- [x] 후속 장비 비교 태스크가 현재 장착 장비와 후보 장비의 데이터를 읽을 수 있다.

## Constraints and risks

- 게임플레이·저장 모델 변경은 콘솔과 Unity 구현을 함께 갱신한다.
- 기존 저장 파일에는 장비 정보가 없으므로 하위 호환 기본값이 필요하다.
- 세부 장비 모델과 획득 경로를 브레인스토밍 및 엔지니어링 리뷰에서 확정한다.
